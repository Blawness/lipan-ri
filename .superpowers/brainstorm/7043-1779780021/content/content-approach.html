Bagaimana konten akan dikelola?

Ini menentukan arsitektur keseluruhan project

A

Static Site — Hardcode konten di file MDX

Semua artikel, halaman, dan foto ditulis manual sebagai file .mdx di dalam repo. Tidak perlu database atau admin panel. Cocok jika konten jarang berubah dan kamu ingin performa maksimal serta deployment super simpel.

Pros

  • Performa tertinggi (static generation)
  • Tidak perlu database
  • Deployment simpel (Vercel/static)
  • Full version control konten

Cons

  • Tidak ada dashboard admin
  • Edit konten harus lewat kode
  • Non-teknisi tidak bisa update
B

Headless CMS — Admin panel terpisah (Strapi / Payload)

Konten dikelola lewat dashboard admin yang user-friendly. Next.js mengambil data via API (REST/GraphQL). Cocok jika butuh admin panel tapi tidak mau bikin dari nol.

Pros

  • Dashboard admin siap pakai
  • Non-teknisi bisa posting artikel
  • API auto-generated

Cons

  • Perlu hosting terpisah / lebih kompleks
  • Overkill jika konten jarang update
  • Kustomisasi terbatas
C

Database + Admin built-in — Full custom

Next.js dengan database (PostgreSQL + Prisma/Drizzle) dan admin panel built-in. Kontrol penuh atas semua fitur. Cocok jika kamu ingin sistem lengkap dengan auth, roles, dsb.

Pros

  • Kontrol penuh
  • Bisa dikembangkan tanpa batas
  • One repo untuk semuanya

Cons

  • Development paling lama
  • Perlu bikin admin panel dari nol
  • Maintenance lebih berat
